## 1. 产品结构

```text
周末职得
├─ 落地页 #/
│  ├─ 价值主张 / 搜索入口
│  ├─ 角色入口（学生 / 商家 / 运营）
│  └─ 推荐班次 / 使用说明 / 信任说明
│
├─ 学生视角
│  ├─ 发现 #/student
│  ├─ 岗位详情 #/student/jobs/:jobId
│  ├─ 我的兼职 #/student/gigs
│  └─ 工作卡 #/student/work/:orderId
│
├─ 商家视角
│  ├─ 工作台 #/merchant
│  ├─ 发布岗位 #/merchant/jobs/new
│  ├─ 岗位管理 #/merchant/jobs
│  ├─ 候选人 #/merchant/jobs/:jobId/applicants
│  └─ 履约与结算 #/merchant/fulfillment
│
└─ 运营视角
   └─ 控制台 #/admin
      ├─ 概览
      ├─ 认证审核
      ├─ 岗位巡检
      └─ 纠纷处理
```

### 1.1 导航

**学生移动端底部导航：**

```text
[发现]  [我的兼职]  [消息]
```

**商家移动端底部导航：**

```text
[工作台]  [岗位]  [履约]
```

**消息与个人：** 顶部铃铛打开消息抽屉；右上角头像打开个人抽屉（信用、技能、空闲时间、认证状态、重置入口）。不单独做页面，减少范围。

**桌面端：** 左侧窄侧栏 + 顶部角色切换；内容区最大宽度 1120px。

**通用顶栏：**

```text
周末职得  [学生 | 商家 | 运营]   [演示环境]  [重置]
```

## 2. 页面规格

### 2.1 落地页 `#/`

**目标：** 10 秒内说清楚「这是什么、为谁解决什么、下一步点哪」。

**结构：**

1. 顶部品牌 + 演示标识。
2. Hero：
   - 标签：「大学城 3km · 周末短工」
   - 主标题：「周末两天空档，找点**值得**做的事」
   - 副标题：「附近商家、真实班次、工资托管。周六周日，赚点生活费，也攒点经验。」
   - 搜索框：「搜咖啡师、花店帮工、活动执行…」
   - 双 CTA：「我是学生，找班次」「我是商家，去招人」
3. 信任条：`已认证商家 12` / `本周班次 18` / `0 押金`（标注演示数据）。
4. 推荐班次：3 张岗位卡。
5. 三步说明：`看班次 → 报名等录用 → 到岗结算`。
6. 双边价值：学生卡 / 商家卡。
7. 信任与安全：认证、托管、签到留痕、双向评价。
8. 页脚：演示声明、隐私说明、非真实招聘声明。

**交互：**

- 搜索提交 → 学生发现页并带入关键词。
- 「我是学生」→ 学生视角；「我是商家」→ 商家视角。
- 岗位卡 → 详情。

**空/异常：** 无。

---

### 2.2 学生发现 `#/student`

**目标：** 快速找到「这周末能去、距离合适、钱合适」的班次。

**结构：**

```text
┌──────────────────────────────────────┐
│ 星湖大学城 · 南校区     距离 2km ▾   │
│ 搜「咖啡师 / 花店 / 活动执行」        │
│ [全部] [餐饮] [零售] [活动] [宠物] … │
│ [本周末] [周六] [周日]   筛选 ▾       │
├──────────────────────────────────────┤
│ 为你匹配 6 个班次        按匹配度 ▾   │
│ ┌──────────────────────────────────┐ │
│ │ 拾光咖啡 · 1.2km      匹配 95     │ │
│ │ 周末咖啡师助手                    │ │
│ │ ¥160/天  周六 10:00–18:00  剩1人  │ │
│ │ [咖啡][沟通]  工资已托管（模拟）  │ │
│ └──────────────────────────────────┘ │
│ …                                    │
└──────────────────────────────────────┘
```

**字段：**

- 岗位标题、商家名、类别、封面渐变；
- 计薪（日薪/时薪）、班次日期与时间；
- 距离、剩余名额、匹配分；
- 技能标签、托管标识、加急标识。

**筛选：**

- 关键词：标题、商家、技能；
- 类别：全部/餐饮/零售/活动/宠物/其他；
- 日期：本周末/周六/周日；
- 距离：1km/2km/3km；
- 排序：匹配度/距离/薪资。

**状态：**

- 无结果：插画 + 「换个关键词，或放宽距离」+ 重置按钮。
- 已满员：卡片置灰，显示「可候补」。
- 已报名：显示「已报名」并禁用重复入口。

---

### 2.3 岗位详情 `#/student/jobs/:jobId`

**目标：** 让学生在做决定前看到所有关键信息，降低不确定感。

**结构：**

1. 封面渐变 + 类别 + 商家名 + 认证标识 + 评分。
2. 标题 + 匹配分环 + 匹配理由。
3. 薪资卡：`¥160/天`、`周六 10:00–18:00`、`1.2km · 骑行约 6 分钟`。
4. 班次选择：日期、时间、剩余名额、状态。
5. 工作内容（3–5 条）。
6. 要求与加分项。
7. 地点：模糊地址 + 距离 + 「录用后显示详细地址」。
8. 商家信任：认证、评分、完成单数、履约率、托管状态。
9. 规则：取消、签到、结算、评价。
10. 底部固定：「报名这个班次」+ 薪资。

**匹配解释卡：**

```text
为什么推荐给你
✓ 时间完全匹配：周六 10:00–18:00
✓ 距离 1.2km，骑行约 6 分钟
! 需要基础咖啡制作经验，可在备注说明
```

**报名弹窗：**

- 已选班次；
- 冲突检查结果（通过/红色提示）；
- 备注（选填，≤100 字）；
- 勾选「已阅读取消与结算规则」；
- 提交按钮。

**异常：**

- 冲突：红色 banner，按钮禁用；
- 已满：引导「加入候补」；
- 已报名：显示状态，不重复提交。

---

### 2.4 我的兼职 `#/student/gigs`

**分组：**

```text
[待确认] [待上岗] [进行中] [待结算] [已完成]
```

**卡片：**

- 岗位、商家、班次、薪资、状态；
- 下一步按钮：撤回报名 / 查看工作卡 / 去签到 / 去评价 / 查看结算；
- 已取消：显示原因与信用影响。

**空状态：** 「这周末还没安排？去看看附近班次」+ CTA。

---

### 2.5 工作卡 `#/student/work/:orderId`

**目标：** 到岗当天的「唯一入口」，不用翻聊天记录。

**结构：**

1. 状态时间线：报名 → 录用 → 签到 → 签退 → 结算。
2. 商家地址、联系人（录用后可见）、营业时间。
3. 签到码：4 位数字（如 `4821`），大字号。
4. 模拟地图块：`拾光咖啡 · 距你 80m`（不接真实地图）。
5. 到岗清单：穿黑色围裙、提前 10 分钟到、找店长陈姐。
6. 操作按钮：
   - 未签到：「到店签到」
   - 已签到：「签退」
   - 已签退：「等待商家确认」
   - 已完成：「查看结算 / 去评价」
7. 演示提示：「签到时间窗口与定位为模拟，演示模式已放宽」。

**签到弹窗：**

- 输入 4 位签到码；
- 模拟定位状态：`已到店（80m）`；
- 确认签到；
- 错误码：`签到码不正确` / `不在签到时间` / `已签到`。

**签退：** 确认弹窗显示「本次工时 8 小时，工资 ¥160（模拟）」。

---

### 2.6 商家工作台 `#/merchant`

**目标：** 一屏看清「这周缺不缺人、谁要我处理、钱结没结」。

**结构：**

1. 店铺头：店名、认证、评分、地址。
2. 指标卡：本周班次 / 待处理报名 / 缺人班次 / 履约率。
3. 待办：
   - 「周六 10:00 咖啡师还缺 1 人」→ 去候选人；
   - 「林小满报名了，待处理」→ 去处理；
   - 「周日的班已满」。
4. 本周排班表：日期、班次、人数、状态、到岗数。
5. 快捷操作：发布岗位 / 看候选人 / 履约结算。
6. 最近评价。

---

### 2.7 发布岗位 `#/merchant/jobs/new`

**目标：** 3 分钟内发一个周末班次，不写长文。

**三步：**

**Step 1 基本信息**

- 岗位模板：咖啡店 / 零售 / 活动 / 宠物 / 自定义；
- 岗位标题；
- 类别；
- 工作内容（模板自动填充，可改）；
- 封面渐变自动生成。

**Step 2 班次与薪资**

- 日期（默认下周六）；
- 开始/结束时间；
- 招聘人数；
- 计薪方式（日薪/时薪）；
- 金额；
- 地址（校区周边区域）；
- 自动预估总成本：`人数 × 日薪`；服务费显示 `¥0（试点期免佣）`。

**Step 3 要求与预览**

- 要求（3 条以内）；
- 加分技能；
- 是否加急；
- 预览卡片；
- 「发布岗位」。

**校验：**

- 时间结束必须晚于开始；
- 单班次 ≤ 8 小时；
- 人数 1–20；
- 金额 > 0；
- 标题 ≤ 30 字。

**发布后：** 岗位进入「招募中」，学生端可见；toast「发布成功，已开始匹配」。

---

### 2.8 岗位管理 `#/merchant/jobs`

- 列表：招募中 / 已满 / 已结束；
- 每项显示报名数、已录用、剩余名额；
- 操作：看候选人、暂停/恢复、关闭；
- 已产生录用记录的岗位，关键信息不可改，只能关闭或新增班次。

---

### 2.9 候选人 `#/merchant/jobs/:jobId/applicants`

**结构：**

```text
周末咖啡师助手 · 周六 10:00–18:00 · 1/2
[待处理 3] [已录用 1] [候补 1]

┌──────────────────────────────────────┐
│ 林小满  星湖大学 · 大二     匹配 95  │
│ 信用 108 · 完成 7 单 · 咖啡/沟通     │
│ ✓ 时间完全匹配  ✓ 距离 1.2km         │
│ 备注：周六全天有空，做过咖啡店兼职   │
│ [拒绝] [候补] [录用]                 │
└──────────────────────────────────────┘
```

**交互：**

- 录用：确认弹窗「录用后将占用 1 个名额」→ 成功 toast；
- 满员后录用按钮禁用，提示「班次已满，可加入候补」；
- 拒绝/候补即时更新状态；
- 候选人卡片可展开查看完整档案、评价、信用记录。

**空状态：** 「还没有人报名，试试把岗位分享到班级群」+ 复制文案按钮（演示）。

---

### 2.10 履约与结算 `#/merchant/fulfillment`

- 按日期/班次分组；
- 名单：学生、签到状态、签到时间、工时、结算状态；
- 操作：
  - 未签到：`标记爽约`（二次确认）；
  - 已签退：`确认工时`；
  - 已确认：显示「已结算（模拟）」；
- 结算汇总：工资、服务费 ¥0、实付；
- 评价入口。

**确认工时弹窗：**

```text
确认 林小满 的工时？
班次：周六 10:00–18:00
工时：8 小时
工资：¥160（模拟托管释放）
[取消] [确认并结算]
```

---

### 2.11 运营控制台 `#/admin`

**四个 tab：**

1. **概览**：本周班次、履约率、待审核、纠纷数、Top 类别。
2. **认证审核**：待审核商家列表 → 查看资料（营业执照占位图、门店信息）→ 通过/驳回（填原因）。
3. **岗位巡检**：异常岗位列表（薪资异常、描述不清、被举报）→ 通过/下架。
4. **纠纷处理**：纠纷列表 → 订单时间线（报名、录用、签到、签退、确认）→ 双方陈述 → 处理：
   - 全额释放；
   - 部分退款；
   - 驳回；
   - 填写处理说明。

**演示数据：** 1 个待审核商家、1 个待巡检岗位、1 个待处理纠纷。

## 3. 核心流程

### 3.1 学生报名

```text
发现页 → 岗位详情 → 选择班次 → 报名弹窗
→ 冲突校验（通过）→ 勾选规则 → 提交
→ 我的兼职「待确认」→ 商家端出现候选人
```

### 3.2 商家录用

```text
工作台待办 → 候选人列表 → 查看匹配理由/信用
→ 录用 → 名额 -1 → 学生「待上岗」
→ 其他候选人可选择候补
```

### 3.3 到岗与结算

```text
学生工作卡 → 输入签到码 → 模拟定位 → 签到成功
→ 商家到岗名单更新 → 学生签退
→ 商家确认工时 → 模拟释放工资
→ 学生钱包 +¥160 → 双方评价 → 信用 +1
```

### 3.4 取消与候补

```text
已录用学生取消
→ 按时间规则扣信用
→ 释放名额
→ 自动通知候补第一位
→ 候补变为已录用（演示自动确认）
```

### 3.5 运营处理

```text
认证审核：待审核 → 通过/驳回 → 商家状态更新
岗位巡检：异常岗位 → 下架 → 学生端不可报名
纠纷：查看时间线 → 选择处理 → 记录结果
```

## 4. 设计系统

### 4.1 视觉方向

**关键词：** 清爽、可信、年轻、有行动感。

不要：招聘网站式的蓝白密集表格、过度娱乐化的插画、金融科技式的冷感。

### 4.2 色彩

| Token | 值 | 用途 |
|---|---|---|
| `--brand` | `#18A957` | 主按钮、选中态、品牌 |
| `--brand-dark` | `#0E7A3E` | hover/强调 |
| `--accent` | `#FF7A1A` | 加急、薪资、重点数字 |
| `--ink` | `#10231A` | 标题 |
| `--body` | `#40524A` | 正文 |
| `--muted` | `#6B7C74` | 次要信息 |
| `--bg` | `#F4F7F4` | 页面背景 |
| `--card` | `#FFFFFF` | 卡片 |
| `--line` | `#E2E9E3` | 分割线 |
| `--warn` | `#B45309` | 警告 |
| `--danger` | `#C2410C` | 错误/取消 |
| `--info` | `#0369A1` | 信息 |

封面渐变示例：

```css
--cover-cafe: linear-gradient(135deg, #F3E3D3, #C99A6B);
--cover-pet: linear-gradient(135deg, #E7F0E4, #8FBF8A);
--cover-flower: linear-gradient(135deg, #FBE4EA, #E8A0B4);
--cover-event: linear-gradient(135deg, #E4E9F7, #8FA3D9);
```

### 4.3 字体与排版

```css
font-family: "PingFang SC", "Microsoft YaHei", "Noto Sans SC", system-ui, sans-serif;
```

| 层级 | 字号/行高 | 用途 |
|---|---|---|
| H1 | 32/40（移动 28/36） | 落地页主标题 |
| H2 | 24/32 | 页面标题 |
| H3 | 18/26 | 卡片标题 |
| Body | 15/24 | 正文 |
| Small | 13/20 | 辅助信息 |
| Number | 28/32，tabular-nums | 薪资/匹配分 |

### 4.4 间距与形状

- 8px 栅格；页面边距 16/20/24；
- 卡片圆角 20；按钮 12；标签 999；
- 阴影：`0 8px 24px rgba(16,35,26,.06)`；
- 触控目标 ≥ 44px；
- 内容最大宽度 1120px。

### 4.5 核心组件

| 组件 | 说明 |
|---|---|
| `JobCard` | 封面渐变、商家、标题、薪资、时间、距离、匹配分、剩余名额 |
| `MatchRing` | 0–100 圆环，颜色按分段：≥85 绿 / 70–84 橙 / <70 灰 |
| `StatusPill` | 待确认/待上岗/进行中/待结算/已完成/已取消 |
| `ShiftChip` | 日期 + 时间段 + 剩余名额 |
| `TrustRow` | 认证、评分、完成单数、托管 |
| `DemoBanner` | 顶部固定演示说明 |
| `BottomBar` | 移动端固定操作栏 |
| `Modal` | 焦点陷阱、Esc 关闭、移动端底部抽屉 |
| `EmptyState` | 图标 + 一句解释 + 一个下一步 |

### 4.6 文案原则

- 说人话，不用「赋能/闭环/生态」。
- 给确定信息：几点、在哪、多少钱、做什么。
- 不承诺绝对安全：用「工资已托管（模拟）」「商家已认证」，不用「平台担保零风险」。
- 不制造焦虑：不用「再不报名就没了」。
- 禁用词：躺赚、暴富、日入过千、轻松兼职、学生妹。

### 4.7 响应式

| 断点 | 布局 |
|---|---|
| `< 640px` | 单列卡片、底部导航、固定操作栏、筛选抽屉 |
| `640–1024px` | 双列卡片、顶部导航 |
| `> 1024px` | 左侧栏 + 三列/两列内容、右侧信息栏 |

## 5. 种子数据

> 所有日期基于「下一个周末」动态生成，保证任何时候打开都有可报名班次。

### 5.1 演示账号

## 6. 3 分钟演示脚本

**准备：** 打开本地预览或已部署链接，确认顶部「演示环境」标识；点击「重置演示数据」。

| 时间 | 操作 | 期望 |
|---|---|---|
| 0:00–0:20 | 落地页讲解：3km、周末班次、工资托管 | 首屏清楚表达定位 |
| 0:20–0:50 | 切学生 → 发现页 → 筛选「周六」→ 打开「周末咖啡师助手」 | 看到匹配 95、时间/距离/薪资、托管标识 |
| 0:50–1:05 | 点击报名 → 勾选规则 → 提交 | 成功，进入「待确认」 |
| 1:05–1:30 | 切商家 → 工作台 → 候选人 → 录用林小满 | 名额变为 2/2，学生状态「待上岗」 |
| 1:30–2:00 | 切学生 → 我的兼职 → 工作卡 → 输入签到码 4821 → 模拟定位签到 | 状态「进行中」，商家端到岗 |
| 2:00–2:20 | 签退 → 切商家 → 履约 → 确认工时 | 模拟结算，工资释放 |
| 2:20–2:40 | 切学生 → 评价 5 星 → 查看信用/钱包 | 信用 +1，钱包 +¥160 |
| 2:40–3:00 | 切运营 → 认证审核 / 纠纷 | 展示平台治理能力 |
| 3:00 | 刷新页面 | 数据仍在，证明持久化 |

**讲解重点：**

1. 为什么以班次为单位，而不是岗位。
2. 为什么工资托管和信用是撮合的前提。
3. 候补补位如何解决商家最痛的爽约。
4. 运营视角如何控制虚假岗位与纠纷。
